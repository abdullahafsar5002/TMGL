# TMGL Architecture

**Last updated:** 2026-09-18 (Phase 4 — Release)

## System Overview

TMGL is a golf league management platform with three client experiences sharing a single Supabase backend.

```
┌─────────────────────────────────────────────────────────┐
│                    Supabase Backend                      │
│  ┌──────────┐  ┌──────────┐  ┌──────────────────────┐  │
│  │ PostgreSQL│  │ Auth     │  │ Row Level Security   │  │
│  │ (14 tables)│ │ (email) │  │ (role-based policies)│  │
│  └──────────┘  └──────────┘  └──────────────────────┘  │
└──────────────┬──────────────────────────┬───────────────┘
               │                          │
    ┌──────────▼──────────┐    ┌──────────▼──────────┐
    │   Web / PWA Client  │    │  Android Client     │
    │   (React + Vite)    │    │  (Kotlin + Compose) │
    │                     │    │                     │
    │  • supabase-js      │    │  • supabase-kt      │
    │  • Service layer    │    │  • Repository layer │
    │  • Vercel deploy    │    │  • APK/AAB build    │
    └─────────────────────┘    └─────────────────────┘
```

### Data Flow
```
Page Component
  → Service Layer (lib/league.ts or lib/competition.ts)
    → Supabase Client (lib/supabase.ts)
      → Supabase API (PostgREST + GoTrue)
        → PostgreSQL (RLS enforced)
```

### Authentication Flow
1. User submits credentials → `AuthContext.signIn()`
2. Supabase Auth validates → returns Session
3. `onAuthStateChange` fires → `AuthContext` updates state
4. Profile loaded from `profiles` table → role determined
5. `ProtectedRoute` checks session + role → allows/blocks access

### Toast Notifications
The app provides user feedback via toast notifications:
```typescript
// Usage in any component
const toast = useToast();
toast.success('Player created successfully');
toast.error('Failed to save scorecard');
toast.info('New season available');
toast.warning('Scorecard not verified');
```
- Animated slide-in from right
- Auto-dismiss (5s for success/info, 8s for errors)
- Manual dismiss with aria-label
- `aria-live="polite"` for screen readers

### Code Splitting
All non-core routes are lazy-loaded via `React.lazy()`:
```typescript
// src/router/AppRouter.tsx
const DashboardPage = React.lazy(() => import('./pages/DashboardPage'));
const SeasonsPage = React.lazy(() => import('./pages/SeasonsPage'));
// ... 24 more lazy-loaded pages
```
- Main bundle: 471KB (down from 640KB, -26%)
- Each page loads independently
- `Suspense` wrapper shows loading indicator

### Role Hierarchy
```
public (0) < player (1) < league_manager (2) < super_admin (3)
```

## PWA

### Configuration
- **Manifest:** Generated by `vite-plugin-pwa` (auto-update mode)
- **Service Worker:** Workbox precache (index.html, CSS, JS, icons, offline.html)
- **Display:** standalone, portrait orientation
- **Theme Color:** #0B3D2E (golf green)
- **Icons:** SVG at 192x192 and 512x512 (any + maskable)
- **Precached Entries:** 60 (725 KiB)

### Behavior
- Auto-updates when new version available (no user prompt)
- SPA routing fallback (all routes → index.html)
- Navigate fallback to index.html for SPA routing
- Offline fallback page (`/offline.html`) for network failures
- Precaches static assets on install

### Caching Strategy
| Resource | Strategy | Notes |
|----------|----------|-------|
| Static assets | CacheFirst | Cached on precache |
| Supabase API | NetworkFirst | 5min expiry, 5s timeout |
| Page navigations | NetworkFirst | Falls back to offline.html |
| Images | CacheFirst | Runtime cache |

## Android Application

### Architecture Decision
The Android app is a **native Kotlin/Jetpack Compose application**, NOT a Capacitor WebView wrapper.

**Evidence:**
- `MainActivity.kt` extends `ComponentActivity` with `setContent { }` (Compose)
- No WebView usage in any Activity or Fragment
- Supabase Kotlin SDK called directly (no Capacitor bridge)
- Vestigial Capacitor files removed in Phase 2

## Database Schema

### Tables (14)
| Table | Purpose |
|-------|---------|
| profiles | User profiles (auto-created via trigger) |
| seasons | League seasons |
| divisions | Season divisions |
| players | Player records |
| teams | Teams per season |
| team_members | Team-player associations |
| courses | Golf courses |
| course_holes | Hole definitions per course |
| tournaments | Tournaments per season |
| rounds | Rounds per tournament |
| matches | Matches per round |
| scorecards | Player scorecards per round |
| scorecard_holes | Hole-by-hole scores |

### Enums
- `user_role`: public, player, league_manager, super_admin
- `season_status`: draft, active, completed, archived
- `tournament_status`: draft, open, closed, live, completed, cancelled
- `match_status`: draft, scheduled, live, completed, cancelled
- `scorecard_status`: draft, in_progress, submitted, verified, rejected, amended
- `match_type`: singles, foursome, fourball, team

### RLS Strategy
- **Public read:** Active seasons, players, teams, tournaments, matches
- **Owner read:** Own profile, own scorecards
- **Manager write:** CRUD on all league entities
- **Manager write (storage):** Upload/update/delete team logos
- **Super admin:** Full access including user management
- **Function:** `get_user_role()` SECURITY DEFINER prevents recursive RLS
- **Trigger:** `handle_updated_at()` auto-updates timestamps on all tables

### Storage
- **Bucket:** `team-logos` (public read, manager write)
- **Upload:** Authenticated users with manager role
- **Validation:** JPG/PNG/WebP, max 5MB

## Accessibility

### Web
- **Focus indicators:** Gold `2px solid` outlines on all interactive elements
- **Keyboard navigation:** All features accessible via keyboard
- **Mobile menu:** Escape key closes, focus returns to trigger
- **Forms:** Labels associated with inputs, error messages announced
- **ARIA:** `aria-expanded`, `aria-controls`, `aria-live="polite"` regions
- **Touch targets:** Minimum 44px for all interactive elements
- **Screen readers:** Toast notifications, loading states, empty states

### Android
- **Material3:** Built-in accessibility support
- **Content descriptions:** All images and icons
- **Touch targets:** Minimum 48dp (Material guideline)
- **Contrast:** WCAG AA compliant with TMGL palette

## Deployment

### Web/PWA
- **Platform:** Vercel
- **Build:** `npm run build` → `dist/`
- **Config:** SPA rewrites in `vercel.json`
- **PWA:** Service worker auto-updates
- **Security Headers:** CSP, X-Content-Type-Options, Referrer-Policy

### Android
- **Debug APK:** `./gradlew assembleDebug`
- **Release APK:** `./gradlew assembleRelease` (requires keystore)
- **AAB:** `./gradlew bundleRelease` (for Play Store)
- **Credentials:** `local.properties` (gitignored)
- **ProGuard:** Serialization, Ktor, Supabase keep rules
