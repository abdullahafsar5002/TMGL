### Migration 0005 Enum Issue & Resolution
Migration 0005 defines `match_type` enum using `create type public.match_type as enum (...)`. The enum was created **before** the `tournaments` table in migration 0001 which uses `tournament_status` enum. The `match_type` enum creation is non-destructive (uses `as enum` not `if not exists`, but this is fine for CREATE TYPE which is atomic). No errors occurred during application — the enum type `public.match_type` was created successfully and referenced correctly by the `matches` table.

### Migrations 0006–0008: Post-Application Verification
- **0006:** `handle_updated_at()` trigger function created and applied to 10 tables (profiles, seasons, players, teams, courses, tournaments, rounds, matches, scorecards, scorecard_holes). Also replaced deprecated `auth.role() = 'authenticated'` with `auth.uid() IS NOT NULL` for courses and course_holes read policies, added missing seasons DELETE policy, and course_holes UPDATE policy.
- **0007:** `team-logos` storage bucket created (public). Initial permissive policies allowed any authenticated user to upload/update/delete. No errors during application.
- **0008:** Tightened storage policies — dropped permissive policies from 0007, replaced with manager-only policies using `get_user_role() IN ('super_admin', 'league_manager')`. Added missing DELETE policies for courses and course_holes tables.
